# container-ocr

Предметная логика распознавания морского контейнера поверх строк OCR: кандидаты кода,
атрибуты (типоразмер, веса) и межкадровое голосование за код. Конфиг сканера и выбор
регионов — в `features/container-scan`.

## Public API

| Экспорт                                                                                                 | Что                                                                           |
| ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `computeIso6346CheckDigit`, `isValidIso6346`, `parseIso6346`                                            | контрольная цифра и разбор кода (`owner`, `category`, `serial`, `checkDigit`) |
| `decodeIso6346SizeType`, `decodeEquipmentCategory`                                                      | расшифровка типоразмера (`45G1`) и категории (`U`/`J`/`Z`)                    |
| `resolveOwnerName`, `formatContainerCode`                                                               | имя линии по коду владельца; `"MSCU 123456-7"`                                |
| `extractContainerCandidates(observations)`                                                              | кандидаты кода из OCR-областей (worklet)                                      |
| `extractContainerAttributes(sources)`, `mergeContainerAttributes`                                       | типоразмер и веса кадра; слияние между кадрами                                |
| `accumulateContainerCandidates`, `resolveContainerCode`                                                 | голосование за валидные коды между кадрами и вывод подтверждённого кода       |
| `IContainerAttributes`, `IContainerAttributeSources`, `IContainerWeights`, `EMPTY_CONTAINER_ATTRIBUTES` | атрибуты и их источники                                                       |
| `IContainerCandidate`, `IContainerCodeParts`, `IContainerSizeType`, `IContainerRect`                    | типы                                                                          |

## Устройство

- Кандидаты: одиночные области, пары соседних (`"MSCU"` + `"123456 7"`) и вертикальные
  стопки; похожие символы подменяются по позиции (буквы владельца ↔ цифры серийника),
  ложные комбинации отсеивает контрольная цифра. Первый вариант источника попадает в
  кандидаты всегда (для оверлея), остальные — только валидные.
- Источники атрибутов разложены по регионам детектора (`sizeType`, `weightPlate`,
  `maxGross`, `tare`, `net`); без детектора кадр целиком идёт в `sizeType` и
  `weightPlate`.
- Веса: поле из своего региона (число с единицей кг, иначе меньшее правдоподобное —
  килограммы меньше фунтов) приоритетнее разбора таблички; табличка — по меткам, затем по
  тождеству брутто = тара + нетто; нетто добирается вычитанием.
- `framesSinceCode` считает кадры после подтверждения кода — окно, в котором домен ждёт
  типоразмер и веса.
- Покрыто тестами: `iso6346`, `candidates`, `attributes`.

## Зависимости

- `shared/lib/ocr-scan` (типы кандидата и подтверждения), типы
  `react-native-vision-engine`.
- Потребители: `features/container-scan`, `pages/stack/container-scanner`.

## Gotcha

- В склейке участвуют только фрагменты из 1–10 символов, иначе бюджет комбинаций
  сгорает на постороннем длинном тексте в кадре.
- Вес вне 500–80 000 кг считается непрочитанным — и по меткам, и при вычитании нетто.
- Worklet-код: функции объявляются выше потребителей, RegExp — только внутри тел
  функций (из module scope он не переживает сериализацию в worklet-рантайм).
