# app-state

Отвечает на вопрос «приложение сейчас на переднем плане?» и сообщает о переходах.
Нужен сервисам, которые живут вне React и должны реагировать на уход в фон.

## Public API

| Экспорт            | Что                                                          |
| ------------------ | ------------------------------------------------------------ |
| `IAppStateService` | токен + контракт: `isActive`, `onChange(cb)` → отписка       |
| `AppStateService`  | реализация на `AppState` из `react-native`                   |
| `appStateModule`   | DI-модуль: `IAppStateService` → `AppStateService`, singleton |

## Устройство

- `app-state.types.ts` — токен и интерфейс, `app-state.service.ts` — реализация,
  `app-state.module.ts` — биндинг. Модуль регистрируется в `app/app.module.ts`.
- `onChange` сообщает только о смене активности: активным считается лишь `"active"`,
  `inactive`/`background` — неактивно.

## Зависимости

- `@shared/lib/di` — токен.
- Потребитель — `shared/lib/socket` (приостановка сокета в фоне, пробуждение по возвращении).

## Gotcha

- iOS шлёт `inactive` (шторка, системные диалоги) и повторы того же состояния —
  сервис их отбрасывает: колбэк вызывается только при реальном переходе
  активно ↔ неактивно.
