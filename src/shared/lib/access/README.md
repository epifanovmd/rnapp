# access

Чистые функции проверки прав. Не знают ни пользователя, ни бэкенда: на входе — набор
выданных прав и требуемое право.

## Public API

| Экспорт                            | Что                                                  |
| ---------------------------------- | ---------------------------------------------------- |
| `Permission`                       | право — строка `домен:действие[:own]`                |
| `ALL_PERMISSIONS`                  | `"*"` — полный доступ                                |
| `AccessScope`                      | `"all" \| "own"`                                     |
| `hasPermission(granted, required)` | покрывает ли набор право с учётом wildcard и `:own`  |
| `scopeIn(granted, required)`       | `"all"`, `"own"` или `null` — область права в наборе |
| `ownPermission(permission)`        | `x:update` → `x:update:own`                          |

## Устройство

Один файл `permission-grammar.ts`. Право покрывается самим собой, любым wildcard-предком
по сегментам (`project:task:create` ← `project:task:*` ← `project:*`) и `*`. Право на
все сущности покрывает то же право «только на свои»: `x:update` ⊃ `x:update:own`.

`scopeIn` сначала проверяет право целиком (`"all"`), затем его `:own`-вариант (`"own"`).

## Зависимости

Ни от чего не зависит. Потребителей через `@shared/lib/access` пока нет.

## Gotcha

- Обратного покрытия нет: `x:update:own` не даёт `x:update`.
- `entities/user/lib/permissions.ts` содержит собственную копию той же грамматики —
  правки поведения нужно согласовывать с ней.
