# React-компоненты

## Один компонент на файл

Не более одного React-компонента в файле. Относится к экспортируемым и локальным
helper-компонентам, компонентам внутри `memo`/`forwardRef`, render-компонентам
compound API.

- Render-функция, возвращающая `ReactNode` для callback API, не становится
  компонентом, если не используется через JSX и не имеет своего lifecycle.
- Helper-компонент выносится в отдельный файл рядом с потребителем; нужен одному
  компоненту — не экспортируется из public API.

## Ответственность

Компонент — отображение и wiring. Сценарий — в VM-хуке (`use<Name>VM`), состояние
сущности — в сторе, инфраструктура — в сервисе:

```text
Page          — координация экрана
Feature hook  — пользовательский сценарий
Entity store  — состояние сущности
Service       — инфраструктурный side effect
UI component  — отображение
```

Хук выносится, когда логика использует lifecycle/state, повторяется, имеет
предметное имя или мешает читать render, — не ради уменьшения файла.

## Мемоизация и ref

- `memo` — по измеримой причине или когда стабильность — часть существующего
  performance-контракта. Не снимать мемоизацию ради структурного правила — разделить
  реализацию и обёртку корректно.
- `forwardRef`-компоненту задаётся display name, если инструменты не выводят его.

## Props

- Props называются `I<Component>Props` или `<Component>Props` — по принятому в модуле
  стилю; внутри модуля стиль не смешивается.
- Интерфейс пропсов объявляется в файле компонента, над компонентом, и экспортируется,
  если нужен снаружи. Отдельный `<component>.types.ts` — когда типов несколько
  (пропсы, варианты, колбэки) или их импортируют другие файлы модуля. Инлайн-тип в
  сигнатуре не используется. Существующий код приводится к правилу при правке файла.
