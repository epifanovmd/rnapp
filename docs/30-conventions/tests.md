# Тесты

- Тест проверяет наблюдаемое поведение, а не внутреннюю реализацию.
- Исправление дефекта начинается с теста, падающего на текущем коде
  ([process/bugfix](../10-process/bugfix.md)); тест остаётся.
- Snapshot не единственная проверка важной бизнес-логики.
- Тесты лежат рядом с кодом в `__tests__/`; mocks — рядом с тестом или в тестовой
  инфраструктуре модуля (`testing/`).
- Тесты не зависят от порядка запуска и очищают изменённое глобальное состояние.
- Тест не ходит в реальную сеть: транспорт и API подменяются.
- Сгенерированный код напрямую не тестируется — тестируется адаптер или потребитель.
- Модули с порогом покрытия не меняются без тестов до порога.

Настройка тестов проекта и зоны с порогом — [tech/testing](../50-tech/testing.md).
