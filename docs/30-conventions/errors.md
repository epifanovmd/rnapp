# Ошибки и результаты в коде

- Ошибки не игнорируются молча: `if (res.error) return` без показа или обработки —
  дефект.
- Пользовательское сообщение отделяется от технической ошибки.
- Ошибка обрабатывается один раз на подходящем уровне: инфраструктура добавляет
  контекст, сценарий решает, можно ли восстановиться, UI показывает состояние.
- Истечение сессии и ошибки авторизации — централизованно в цикле auth/http.
- Не показывать несколько одинаковых уведомлений из разных уровней одного запроса.
- Новый код сохраняет контракт `{ data } | { error }` и не смешивает его с
  исключениями без отдельного решения.
- Ошибка не превращается в `null`, если `null` означает «нет данных».
