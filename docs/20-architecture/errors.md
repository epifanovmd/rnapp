# Ошибки и уведомления

## Ошибки

- Все API-вызовы возвращают `{ data } | { error }`; исключения наружу не
  выбрасываются.
- Ошибка транспорта нормализуется в типизированный объект с предикатами
  «не авторизован / нет доступа / не найдено / ошибка сервера / сеть / отмена».
- Сетевые и серверные ошибки показываются централизованно, на уровне HTTP-клиента,
  с дедупликацией одинаковых сообщений.
- Отменённый запрос не является ошибкой пользователя и не показывается.
- Ошибки авторизации пользователю не показываются: их обрабатывает цикл обновления
  сессии.
- Одна ошибка сообщается один раз: сценарий не дублирует глобальное уведомление, а
  ошибки, которые глобальный уровень не показывает (4xx), показывает сам.

## Уведомления и глобальные providers

- Источник истины — стор уведомлений (singleton в DI): видимый стек, очередь при
  переполнении, таймеры автоскрытия.
- На один инстанс — два контракта (ISP): публичный сервис для потребителей и
  внутренний контракт для UI-хоста.
- UI-хост монтируется один раз в композиционном корне и своего состояния не имеет;
  уведомления, созданные до его монтирования, отрисовываются при появлении хоста.
- Потребители вызывают контракт и не знают о реализации отображения.
- Расположение providers — [placement](placement.md#providers-и-инфраструктурные-модули).
