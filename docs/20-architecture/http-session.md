# HTTP, сессия и реальное время

Жизненный цикл авторизации — цепочка ответственностей, а не логика в компонентах:

```
хранилище токенов → сервис сессии (refresh, восстановление)
    → HTTP-клиент (middleware) → вызовы API
    → транспорт реального времени (через контракт провайдера токена)
```

Обязательные свойства:

- срок и данные токена — типизированно, через отдельный сервис, а не ручной разбор в
  месте использования;
- проактивное обновление до истечения (с буфером), а не только реакция на 401;
- конкурентные 401 дедуплицируются: все запросы ждут одного обновления и
  повторяются;
- неуспешное обновление очищает сессию через единый канал «сессия истекла»;
- транспорт реального времени переподключается автоматически, а отправка в офлайне
  буферизуется; инициализация идемпотентна;
- подписки на серверные комнаты восстанавливаются после переподключения, а экран
  перечитывает свои данные: события за время обрыва не доставляются.
