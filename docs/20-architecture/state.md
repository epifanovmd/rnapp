# Управление состоянием

## Синхронное состояние домена — сторы

```
entities/<entity>/
  model/
    store.ts            ← класс стора
    types.ts            ← доменные типы и DI-токен интерфейса
  <entity>.module.ts    ← регистрация реализации в контейнере (singleton)
```

- Стор хранит **только состояние и переходы**. Инфраструктура (транспорт, токены,
  хранилище) — в `api`/`lib`.
- Регистрация — явная, через модуль контейнера, не декоратором на классе.
- Зависимости приходят через DI, а не создаются внутри стора.
- Стор не хранит разметку.

## Асинхронное состояние — холдеры

Асинхронные данные не хранятся в ручной паре `useState` + `useEffect`-загрузка. Для
них — единый набор холдеров в `shared/lib`: объекты состояния запроса с React-хуками
поверх (модель, близкая к query-библиотекам).

| Назначение               | Хук             |
| ------------------------ | --------------- |
| одна сущность            | `useEntity`     |
| список                   | `useCollection` |
| постраничный список      | `usePaged`      |
| бесконечная подгрузка    | `useInfinite`   |
| изменяющая операция      | `useMutation`   |
| периодический перезапрос | `usePolling`    |

Каждый холдер — самодостаточная папка: класс состояния, хук, опционально
Provider/Context для шаринга по дереву.

Гарантии любого холдера:

- запрос описывается функцией-загрузчиком, а не императивным кодом в компоненте;
- реактивный перезапрос по зависимостям, условное отключение, загрузка при
  монтировании для запроса без параметров; без явной настройки холдер сам не
  загружается;
- результат — `{ data } | { error }`, исключения наружу не выбрасываются;
- устаревшие ответы игнорируются, фоновая перезагрузка не «моргает» данными.

Холдеры — ядро инфраструктуры с собственным порогом покрытия тестами.
