# Автоматические проверки и исключения

Архитектурные правила машинно проверяемы везде, где это возможно.

| Область                 | Что проверяется                                             | Чем                                   |
| ----------------------- | ----------------------------------------------------------- | ------------------------------------- |
| границы слоёв и слайсов | направление импортов, public API, self-imports              | `eslint-plugin-boundaries`            |
| именование              | имена файлов и директорий                                   | `eslint-plugin-check-file`            |
| функции                 | только стрелочные                                           | `func-style`, `prefer-arrow-callback` |
| импорты                 | порядок и группировка                                       | `simple-import-sort`                  |
| React                   | один компонент на файл, правила хуков, полнота зависимостей | `react`, `react-hooks`                |
| форматирование          | пустые строки между блоками, prettier                       | eslint, prettier                      |
| типы и тесты            | typecheck, зелёные тесты, пороги покрытия                   | tsc, jest                             |

Правило, которое нельзя проверить автоматически, — предмет ревью и описывается в
`docs/30-conventions`.

## Исключения

Исключение из общего правила (файлы, именами которых владеет фреймворк или
кодогенератор или навигатор; платформенные codegen-спеки; сгенерированный код):

1. вызвано требованием фреймворка, генератора, платформы или подтверждённым
   техническим ограничением;
2. максимально узкое;
3. задокументировано рядом с настройкой;
4. не распространяется на новый код автоматически.

Новое исключение — решение пользователя, предлагается через inbox.
