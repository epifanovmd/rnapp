# Слои и сегменты FSD

Приложение строится по [Feature-Sliced Design](https://feature-sliced.design). Шесть
слоёв, каждый строится поверх нижних и не знает о верхних:

```
app → pages → widgets → features → entities → shared
```

Технологии здесь описываются категориями, а не брендами: архитектура не зависит от
конкретной библиотеки. Актуальный стек — [domain/overview](../60-domain/overview.md).

## Слои

| Слой       | Ответственность                                                                     | Контрольный вопрос                             |
| ---------- | ----------------------------------------------------------------------------------- | ---------------------------------------------- |
| `app`      | композиционный корень: запуск, навигатор, глобальные providers, сборка DI, бутстрап | Без этого приложение как система запустится?   |
| `pages`    | экраны — тонкая композиция нижних слоёв под маршрут навигатора                      | Это можно напрямую зарегистрировать как экран? |
| `widgets`  | крупные самостоятельные блоки UI                                                    | Это законченный блок, используемый на экранах? |
| `features` | пользовательские сценарии и действия над сущностями                                 | Пользователь делает это с сущностью?           |
| `entities` | бизнес-сущности: состояние, доменные модели, представление сущности                 | Это существительное предметной области?        |
| `shared`   | переиспользуемый фундамент без знания о бизнес-логике                               | Это пригодилось бы в другом приложении?        |

```
src/
  app/       ← точка входа, конфигурация навигаторов, глобальные providers, DI, бутстрап
  pages/     ← экраны, сгруппированные по навигаторам: <navigator>/<page>/
  widgets/   ← <widget>/
  features/  ← <user-action>/
  entities/  ← <domain-noun>/
  shared/
    ui/      ←   UI-кит
    api/     ←   HTTP-клиенты бэкендов, сгенерированные контракты
    config/  ←   конфигурация окружения
    lib/     ←   независимые технические модули
```

## Слайсы

Слайсы есть в `pages`, `widgets`, `features`, `entities`. Каждый самодостаточен.
У `app` и `shared` слайсов нет: их директории — сегменты или самостоятельные
тематические модули.

- `entities/<domain-noun>/` — одно понятие предметной области;
- `features/<user-action>/` — одно пользовательское действие.

## Сегменты

| Сегмент  | Ответственность                                      |
| -------- | ---------------------------------------------------- |
| `ui`     | отображение, компоненты и связанные стили/форматтеры |
| `model`  | состояние, схемы, бизнес- и сценарная логика         |
| `api`    | запросы, DTO, мапперы, API-адаптеры                  |
| `lib`    | вспомогательный код только этого слайса              |
| `config` | конфигурация и feature flags                         |

- Пустые сегменты не создаются; маленький слайс может быть плоским и раскрывается
  по назначению, когда растёт.
- Сегменты — не мини-слои: направление зависимостей между `ui`, `model`, `api`
  внутри слайса не задано.
- `pages` подчиняется тем же правилам. Группы навигаторов — группы слайсов, а не
  сегменты; общий код в них не кладётся.

## Именование сегментов

Имя описывает назначение, а не вид файла. Новые сегменты `components/`, `hooks/`,
`types/`, `utils/` не создаются. Дополнительный сегмент допустим, если имя выражает
устойчивую ответственность (`validation/`, `navigation/`, `notifications/`).
Существующие legacy-директории с техническими именами образцом не являются.
