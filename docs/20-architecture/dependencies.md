# Правила зависимостей

Модуль слайса импортирует только слайсы **строго нижних** слоёв. Импорт с того же
слоя или сверху запрещён.

| Откуда     | Разрешено                                   |
| ---------- | ------------------------------------------- |
| `shared`   | `shared`                                    |
| `entities` | `shared`                                    |
| `features` | `shared`, `entities`                        |
| `widgets`  | `shared`, `entities`, `features`            |
| `pages`    | `shared`, `entities`, `features`, `widgets` |
| `app`      | всё                                         |

| Нарушение                    | Почему                                                                |
| ---------------------------- | --------------------------------------------------------------------- |
| слайс → слайс того же слоя   | связывает независимые слайсы; общее выносится вниз или через контракт |
| слой → слой выше             | инвертирует направление зависимостей                                  |
| self-import через свой alias | внутри слайса — только относительные пути                             |
| deep import в чужой слайс    | обход public API                                                      |

Границы проверяет `eslint-plugin-boundaries` по принципу «запрещено всё, что не
разрешено явно»; 0 нарушений — условие мержа. Alias-пути объявляются в конфигурации
TypeScript, транспайлера и тест-раннера синхронно — расхождение ломает либо типы, либо runtime.

## Self-imports

Внутри слайса или shared-модуля — только относительные пути:

```ts
import { IStore } from "../model/types"; // ✅ внутри слайса
import { IStore } from "@entities/<entity>"; // ❌ внутри того же слайса
import { IStore } from "@entities/<entity>"; // ✅ из другого слайса
```

Слайс — один элемент линтера, поэтому импорт внутри него — `internal` и разрешён;
запрет alias-варианта — отдельная политика по сырому спецификатору. Правило задано
шаблонами слоёв, новый слайс попадает под него сразу. Темы `shared` — независимые
элементы: друг на друга через alias ссылаться могут, на себя — нет.

## Общий код соседних слайсов

1. Проверить, не одна ли это ответственность — возможно, слайсы надо объединить.
2. Общий бизнесовый код опускается в нижний слой. Валидация, общая для нескольких
   сценариев домена, принадлежит сущности. Общее для нескольких сущностей правило
   без состояния — тематический модуль `shared/lib`.
3. Нижнему слою нужны данные верхнего — Dependency Inversion (ниже).
4. Неизбежная связь между entities — явный cross-public API `@x`, а не deep import.

## Контракты (Dependency Inversion)

Контракт (интерфейс) объявляется внизу, верхний слой его реализует и регистрирует в
DI:

```
shared/lib/<module>/<impl>.ts ──→ shared/lib/<module>/contract/<name>.contract.ts
                                        ↑ implements
entities/<entity>/api/<adapter>.ts ─────┘
```

Инфраструктура (транспорт, хранилище, аналитика) остаётся в `shared`, знание о
домене — в `entities`.
