# Dependency Injection

- Контейнер собирается явно: слайс с биндингами объявляет свой модуль контейнера,
  все модули регистрируются в композиционном корне (`app`).
- Токен и интерфейс объявляются вместе; фабрика токена даёт единый способ получить
  реализацию.
- Обёрточные хуки (`use<X>Store`) не создаются — потребитель обращается к токену
  напрямую.
- Сторы — singleton.

| Где                                      | Как                                |
| ---------------------------------------- | ---------------------------------- |
| в React-компоненте или хуке              | хук получения экземпляра из токена |
| вне React (guard, сервис, инициализация) | синхронное получение из токена     |
| в конструкторе класса                    | декоратор токена в параметре       |

DI применяется на реальных внешних границах (транспорт, хранилище, платформенные
API, доменные сторы), а не для каждого класса с единственной реализацией —
[principles/solid-patterns](../40-principles/solid-patterns.md).

Синтаксис в проекте — [shared/lib/di](../../src/shared/lib/di/README.md).
