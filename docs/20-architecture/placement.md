# Куда положить новый код

Код кладётся на **минимально подходящий** слой. Если место не определяется этим
документом однозначно — вопрос пользователю, а не новое решение.

## Компонент

- Базовый переиспользуемый UI без бизнес-смысла → `shared/ui`.
- Представление сущности → `entities/<entity>/ui`.
- Часть пользовательского действия → `features/<feature>/ui`.
- Крупный законченный блок → `widgets/<widget>/ui`.
- Разметка конкретного экрана → `pages/<page>/ui`.
- Глобальный provider/host, собирающий приложение → `app`.
- Конфигурация навигаторов и экранов → `app`; экран → `pages/<navigator>/<page>`.

## Логика

- Состояние и правила сущности → `entities/<entity>/model`.
- Сценарий действия пользователя → `features/<feature>/model`.
- Состояние только конкретной страницы → `pages/<page>/model`.
- Универсальный технический механизм → тематический модуль `shared/lib`.
- Правило без бизнес-состояния, общее для нескольких сущностей → `shared/lib`;
  сущности строят поверх него своё.
- Инициализация и связывание модулей → `app`.

## API-вызов

- Универсальный HTTP-движок → `shared/lib`; клиенты бэкендов и сгенерированные
  контракты → `shared/api`.
- Запрос, принадлежащий сущности → `entities/<entity>/api`.
- Запрос только ради одного сценария → `features/<feature>/api`.
- Сетевой вызов в `ui` не кладётся.

## Feature или widget

- `feature` — действие пользователя над сущностью: войти, изменить профиль,
  подтвердить операцию, удалить запись. Сценарий «подтвердить → запрос →
  уведомление» — feature, а не VM страницы.
- `widget` — законченный блок композиции: header, панель со списком и действиями,
  крупная карточка из нескольких features.
- Размер файла не делает компонент widget: часть одного действия — `features/<x>/ui`.

## Page

- Соответствует экрану навигатора, собирает нижние слои, содержит только координацию
  экрана. Параметры экрана типизируются рядом с ним.
- Не хранит переиспользуемую бизнес-логику. Часть, нужная нескольким экранам, —
  в widget, feature или entity по её природе.

## Providers и инфраструктурные модули

- Универсальный контракт и сервис (уведомления, хранилище, аналитика, тема) →
  `shared/lib/<module>`.
- Переиспользуемое визуальное представление → `shared/ui/<module>`.
- Provider рядом с shared-модулем — только пока он переносимая часть его API и не
  знает о навигации, сторах и конфигурации приложения. Собирает app-специфичные
  зависимости → `app`; контракт и сервис остаются в `shared`.
- То же для темы, safe area, клавиатуры, модальных хостов: контракт и механика — в
  `shared`, монтирование и порядок вложенности — в `app`.
